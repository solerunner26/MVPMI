## 1. What this app is

A Gujarati-first bilingual **community directory web app** (with an
optional Android WebView shell) for મહુવા ક્ષત્રિય રાજપૂત સમાજ
(Mahuva Kshatriya Rajput Samaj): members enroll, village administrators
verify and forward, the main administrator approves. Node.js + Express +
**SQLite** (a single file — no database server), React-based runtime.

- Version: **0.3.4** (zip built from commit `e5c1304`)
- Canonical repository (public, same code): https://github.com/solerunner26/MVPMI
- Server entry: **`server/index.mjs`** (listens on `process.env.PORT`, default 3000)
- Static frontend: generated into `dist/` by `npm run build`, served by the server
- Database: `data/community.sqlite` (created automatically on first run)

## 4. GoDaddy decision tree

1. Owner logs into GoDaddy → My Products → Hosting → **Manage**.
2. **cPanel (Linux) with "Setup Node.js App"** and a Node version
   **≥ 22.13** → proceed with §5.
3. cPanel but **no Node.js option or Node < 22.13** → **STOP.** Report to

## 5. Deployment steps (cPanel "Setup Node.js App")

1. **Create Application**: Node.js version = highest available **≥ 22.13**;
   Application root = the folder where the zip contents were uploaded
   (the folder containing `package.json`); Application URL = the owner's
   domain/subdomain; Application startup file = **`server/index.mjs`**.
2. **Environment variables** (in the cPanel app panel — never hardcode):
   - `DEVELOPMENT_MODE=true`  *(test deployment — see §6)*
   - `COOKIE_SECURE=true`
   - `PORT=3000`
   - `ADMIN_PASSWORD` = owner's strong password (10+ chars, upper/lower,
     digit, symbol — the server refuses weak ones)
   - `ADMIN_GATE_CODE` = owner's 4 digits
   The owner types the two secrets themselves — do not invent, log or
   echo them.
3. **Terminal** (cPanel Terminal or SSH, in the application root):
   ```bash
   npm ci
   npm run build
   ```
4. **Restart** the application from the cPanel panel.

### If — and only if — the panel refuses `server/index.mjs` as startup file

Some Passenger versions only load CommonJS startup files. In that case
create **one new file** `app.cjs` in the application root with exactly
this content and set it as the startup file:

```js
// app.cjs — Passenger bridge. Runs the real ESM entry unchanged and
// keeps this process alive so the panel manages the lifetime.
const { spawn } = require("node:child_process");
const child = spawn(process.execPath, ["server/index.mjs"], {
  stdio: "inherit",
  env: process.env,
});
child.on("exit", (code) => process.exit(code || 0));
```

**This is the ONLY file you are allowed to add.** If the app still does
not start with either entry, STOP and report — do not modify any project
file. (Fallback then: the VPS path in `docs/RELEASE_ROADMAP.md` §20A.)

## 6. Deployment mode — read carefully

`server/index.mjs` **deliberately refuses to start** unless
`DEVELOPMENT_MODE=true`. This is not an obstacle to work around: it marks
the deployment as a **test deployment with synthetic data only**.
Removing that guard for real community data is an owner decision tied to
documented prerequisites (`docs/RELEASE_ROADMAP.md` §19 "Phase 1",
`docs/RELEASE_AUDIT.md`). **Do not remove, bypass or weaken the guard.**

## 7. Post-deployment verification checklist

Perform over the public HTTPS URL, report each item:

- [ ] Home page loads; Gujarati welcome text visible; no console errors
- [ ] `GET /api/state` returns JSON (`"role":"guest"`, no error)
- [ ] Language toggle (En/ગુ) switches fully — one language at a time
- [ ] Hidden admin gate: 5 taps on the sun logo → 4-digit code screen →
      code + `admin` / owner's password → dashboard loads
- [ ] First sign-in shows the one-time **recovery code** panel
- [ ] A test enrollment can be submitted (synthetic data only)
- [ ] `data/community.sqlite` exists in the application root afterwards
- [ ] Admin → Backup & export → JSON download works
- [ ] The page works on a phone browser (Android Chrome)

## 8. Data, backups, updates

- **All data lives in `data/community.sqlite` on the server.** Phones
  store nothing but a session cookie and preferences.
- Set a **daily backup**: cPanel → Cron Jobs →
  `cp ~/approot/data/community.sqlite ~/backups/community-$(date +\%F).sqlite`
  (create `~/backups` first). Keep 30 days.
- Updating later: upload the new files, `npm ci && npm run build`,
  restart. The database is untouched (it is not in the zip).
